# 使用说明书

## 环境与编译

运行环境是 Windows / .NET Framework 4.x。源码使用 Windows 自带 Framework64 v4.0.30319 C# 编译器，WinForms 和串口 API，无 Python/NuGet 运行依赖。

```powershell
powershell -ExecutionPolicy Bypass -File .\receiver\src\Build.ps1
powershell -ExecutionPolicy Bypass -File .\receiver\src\Test.ps1
```

程序输出至 `receiver/src/build/APT_Receiver.exe`，该目录被 Git 忽略。不要把已有版本的 captures 拷入公开仓库。

## 连接

先将传输模块接入能提供图像和遥测的 FPGA 工程并完成下载。电脑选择实际开发板 COM 口、3000000 / 8N1 / 无流控，点击连接。COM 号以本机设备为准。

程序首次成功连接后记住端口；勾选“插线自动连接”可尝试重连已记住的端口。程序必须保持运行。FPGA SRAM 配置掉电会丢失；Flash 固化属于外部板卡工程的工作，本仓库不提供完整系统固件。

## 三种图像模式

| 控件 | FPGA 命令 | 画面 |
|---|---|---|
| 流畅160×90 | `P` | 低分辨率连续 RGB565 预览 |
| 清晰320×180 | `Q` | 通过 DDR 快照连续发送 RGB565，细节增加、帧率降低 |
| 高清抓图1280×720 | `H` | 一次 RGB888 完整帧；传输结束后图像暂停，遥测恢复 |

程序收到扩展遥测中的 `V:18` 后自动发送所选预览命令，默认 Q。没有版本字段时按旧协议接收，禁用依赖 v18 的控制；没有命令确认包，不能只凭按钮点击判定 FPGA 已执行，需观察实际收到的尺寸和 CRC。

高清传输期间遥测暂停，完成后自动保存 PNG，即使未勾选连续自动保存。点击“恢复预览”继续。当前图像未发完时，FPGA 等其发送完成后再处理模式请求。

## 数据、叠加与保存

右侧显示最新遥测；左上角叠加可关闭。坐标单位是原始1280×720图像的 px，预览缩小不改变其数值基准。模式/AGC/增益仅显示外部回传值。

预览叠加不保证与图像同帧。高清图使用开始收图前的最后一条遥测，带记录时间；右侧仍可继续更新。原工程 HDMI OSD 位于图像传输取点之后，电脑叠加不是 HDMI 字幕像素截图。

“保存PNG”和自动保存均保留接收图像，不包含电脑叠加。运行目录 `captures` 下按会话分目录存储；CSV 字段包括本机时间、坐标、N、模式、AGC、数字增益百分比、固件版本，缺失字段为 -1。原始流记录默认关闭，勾选后会持续写文件，请留意磁盘空间。

## 无硬件演示与回放

```powershell
.\receiver\src\build\APT_Receiver.exe --demo
.\receiver\src\build\APT_Receiver.exe --replay .\sample.bin
```

演示使用生成图像，带 DEMO 标记。回放文件必须是原始协议流，不是 PNG/JPEG 文件。

## 常见问题

| 现象 | 检查方法 |
|---|---|
| 无串口或打开失败 | 检查驱动、USB 线与接口；退出其它占用串口的程序 |
| 只有坐标、没有图像 | 检查 FPGA 图像输入、预览使能、DDR 接口和当前模式 |
| 清晰/高清按钮不可用 | 核对是否收到 `V:18`、是否为3M串口连接、是否在等高清完成 |
| CRC失败 | 检查时钟/波特率偏差、UART复用是否截断、驱动与链路稳定性；失败帧不会显示 |
| 画面清晰度低 | 核对接收尺寸；160×90放大不能生成720p细节，可选320档或720p单帧 |
| 高清后不更新 | 这是保留高清帧的设计行为，点恢复预览 |
| 没有HDMI左上角内容 | 开启电脑数据叠加；本项目不传 HDMI OSD 像素 |
| 传统115200抓图 | 由外部工程提供旧模式切换与触发，单张约4分钟；主路径使用3M |
