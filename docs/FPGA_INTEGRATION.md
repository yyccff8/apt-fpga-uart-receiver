# FPGA 传输模块接入

## 范围

`apt_transport.v` 从原 v18 顶层抽出传输控制，封装串口命令、双时钟预览、快照请求、DDR拷贝和图像/遥测复用。它不生成时钟、不实例化DDR IP，也不采集相机或计算坐标。名称中的 HDMI 时钟域只沿用原工程名称，不要求电脑接收预览时连接 HDMI 显示器。

## 输入与输出约定

| 信号 | 域 | 接入要求 |
|---|---|---|
| `S_rst_n` | 全部 | 低有效复位；集成工程负责各时钟域复位释放约束 |
| `S_hdmi_pixel_clk` | 控制/UART | 固定75MHz，命令接收/遥测/流畅预览发送 |
| `S_csi_rx_clk` | 图像输入 | 连续运行的源像素打包时钟 |
| `S_ddr_clk` | DDR | 固定约66.6667MHz，快照拷贝与高清/清晰发送 |
| `I_rgb[95:0]` | 图像输入 | 每拍四个RGB888像素，首像素在[95:72]，内部R/G/B各8位；数据来自调用方 |
| `I_valid/I_sof/I_last` | 图像输入 | 有效拍/帧首/行末；1280像素对应320个四像素有效拍，沿用源工程信号语义 |
| `I_telemetry_valid` | 控制 | 单周期新遥测脉冲，以下字段应已经同步并稳定，封装延迟一拍触发发送 |
| `I_xc/I_yc` | 控制 | 20位无符号Q12.8坐标，原图px |
| `I_dx/I_dy` | 控制 | 20位有符号Q12.8偏差，原图px |
| `I_n` | 控制 | 20位计数；0表示失锁 |
| `I_mode/I_agc/I_gain_ex` | 控制 | 显示用外部状态；不改变图像算法。增益excess为Q7，0=1×，128=2× |
| `I_uart_rxd/O_uart_txd` | 异步/控制 | PC发单字符命令，FPGA输出协议流 |
| `I_sw4` | 控制输入 | 原工程低有效物理开关，经去抖；不用物理切换时接常高 |
| `I_legacy_grab_pulse` | 控制 | 传统模式抓图脉冲；不用时接0 |
| `S_grab_src[24:0]` | DDR | 最近完成的稳定显示帧槽位基地址；在冻结后到拷贝锁存期间稳定 |
| `O_freeze` | DDR | 快照拷贝期间保护源槽，调用方不得让写入侧覆盖正在拷贝的帧 |
| `S_grab_rd_en/S_grab_wr_en/S_grab_addr/S_grab_wr_data` | DDR | 快照拷贝客户端请求 |
| `S_gr_ready/S_gr_rd_valid` | DDR | 请求真正获准/快照读返回有效 |
| `O_send_rd_en/S_send_addr` | DDR | 图像发送客户端读请求 |
| `S_send_ready/S_send_rd_valid` | DDR | 发送读请求真正获准/其读返回有效 |
| `S_ddr_user_rd_data[127:0]` | DDR | 与相应valid配对的读返回数据，可共享总线但valid必须区分所有者 |
| `O_image_busy` | 跨域组合观察 | 传输保留/拷贝/发送忙的组合指示，仅用于状态；在其它域使用时需同步，不能作为通用时序握手 |

坐标、状态等多位总线的CDC由调用方完成。不要逐位双触发器同步多位变化总线后就认为数值原子一致，应使用稳定数据+事件握手等约定。

## DDR接口

源工程以每行240个128bit字存储RGB888，共172800个字。每字字节为线性像素流，按最高字节先发送。源槽位应是一整帧已完成图像；冻结逻辑必须保护该槽，不应把半写入帧冒充完整帧。

每个128bit传输在本接口的地址增量为 **8**，不是通用字节寻址总线。若你的DDR接口地址单位不同，必须在适配层转换。快照目的基地址默认25,000,000，调用方应确认目的区域与所有源槽、显示槽及其它DMA区域不重叠，并检查物理内存容量。

读/写请求必须保持到真正获准。一个读请求只接受一次，等待对应valid后再继续；不能把“控制器空闲”误当“本客户端已经获准”。读返回要标记所有者，图像发送不能消费显示端返回的数据。

可选参考 `grab_ddr_arbiter.v` 复用了原显示端：视频写优先、显示读计数、后台请求有限等待。其显示FIFO余量/阈值和写侧预留空间是源工程前提，换控制器或显示FIFO需重新核对。调用方也可以使用自己的仲裁器，只要满足上述客户端握手。

## 时钟、波特率与存储参数限制

当前封装固定75MHz/约66.6667MHz和1280×720，不提供任意分辨率的保证。叶级参数虽可修改，但位宽、缓存深度、行步长及边界条件也需一起审查。

流畅路径75MHz/25=3M baud；DDR发送器整数分频22，实际约3.0303M baud，偏高约1%。标称3M接收采样的仿真可解码，但真实驱动/器件稳定性仍需验证。其它时钟下不能只更改约束文件而保留波特率常量。

## 管脚与上板

`constraints/uart_example.adc` 只列HX1P35A原板参考：RX=J1，TX=H1，LVCMOS33。先按自己的板卡版本核对接口方向、电平及约束顶层端口名；约束作用于实际顶层，不是自动作用于子模块端口。

将完整应用工程重新综合、布局、布线并检查时序/CDC后再下载；本仓库没有完整工程、厂商IP或可直接烧写bit。先验证P流畅档，再Q清晰档、H高清与恢复，统计CRC、断连、长时间运行和源槽保护情况。
